# MoonMel 项目提案与技术选型报告 (Proposal)

[English](../en/PRODUCT.md) | [中文说明](./PROPOSAL.md)

本文档记录 MoonMel 项目立项背景、生态现状评估、架构选型权衡及许可兼容性决策。

---

## 1. 立项背景与生态痛点

在现代边缘智能、智能语音、音频事件检测（SED）与端侧机器学习工作流中，音频特征提取是不可或缺的基石阶段。PCM 原始波形由于维度过大且缺乏局部频率表征，无法直接送入紧凑分类模型。

然而在 MoonBit 生态中：
1. 缺乏生产级、数值经过科学对齐的 Mel Filterbank 与 MFCC 提取库。
2. 已有的 DSP 组件存在严重的算法性能限制（如使用递归数组分配的 FFT，单次变换产生百倍堆内存开销）。
3. 部分社区库采用 GPL 许可证，存在开源传染性，无法被商业友好或 MIT 宽松协议的项目集成。

MoonMel 旨在解决这一系列问题，交付一个**纯原生、零外部依赖、MIT 授权、原地算法极致优化、经过 Python 科学标准库严格对齐**的基础设施级音频特征提取引擎。

---

## 2. 依赖审查与架构决策

### 2.1 现有社区生态审查结论
在项目初始化阶段，对当前生态的 DSP 库进行了深度审查：
- **`HK-SHAO/dsp` (v0.1.4)**：其许可证为 **GNU GPLv3**，若直接依赖将导致整个项目被强制传染为 GPLv3，与本项目 MIT 商业友好开源目标冲突；故明确**完全排除**。
- **`chgttyyr/MoonSpectrum` (v0.2.2)**：基于 Apache-2.0 协议，但其 FFT 内核为递归 Cooley-Tukey 实现，每次蝶形变换都会 `push` 与构建新数组，在连续音频分帧（千帧级）运算中会造成剧烈的 WASM 垃圾回收卡顿；且缺少镜像反射填充、Slaney 面积归一化 Mel 滤波器、对数分贝压缩与 MFCC 模块。

### 2.2 架构决策：纯原生自研实现
综合考虑许可证纯洁性、极致内存性能与数值精度控制，MoonMel 决定采用纯原生、解耦自研路线：
1. **纯 MIT 许可**：全自研实现，保证没有任何 GPL 代码片段。
2. **原地位反转与蝶形运算**：避免 GC 内存抖动，单次变换时间缩短一个数量级。
3. **分层多级解耦**：将时域窗函数、快速傅里叶变换、短时傅里叶变换、Mel 滤波器组、MFCC 倒谱以及 WAV 解码器拆分为 7 个自治子包，防止单仓代码臃肿。

## 3. 数值对齐基准选型

选用行业事实标准作为权威对照：
- **基准套件**：`librosa 1.0.0` + `scipy 1.18.1` + `numpy 2.5.3`。
- **参数显式对齐**：窗函数显式设置 `sym=False`（周期窗），STFT 显式设置 `center=True`（反射填充），Mel 显式设置 `htk=False, norm='slaney'`，MFCC 显式设置 `dct_type=2, norm='ortho'`。
- **自动化回归**：通过脚本持久化探针基准向量，任何算法迭代均通过集成测试强制守护误差边界。
